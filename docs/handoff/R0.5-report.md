## 3. Work packages

### WP1: chat request body (done) `23ba597`

- `chat_body(model, &Request) -> Value` is a pure function; `call` uses it and is otherwise unchanged (URL, auth, timeout, streaming, parsing).
- Audio part is `{"type":"input_audio","input_audio":{"data": <request.audio unchanged>,"format":"wav"}}`, still first (audio, image, text). `audio_url` is gone.
- `thinking: {"type": "disabled" | "enabled"}` added; `chat_template_kwargs.enable_thinking` kept; no `reasoning_effort`, no `budget_tokens`; `max_tokens` 512 / 3000 as before. Module comment updated.
- Tests assert exact JSON: part order and content of the audio part with no `audio_url` anywhere in the body; `think` off (`thinking` disabled, `enable_thinking` false, 512, no `stream`, no `reasoning_effort`) and on (enabled, `stream` true, 3000); a text-only body (plain string content, `tools`, `tool_choice: "required"`, `temperature` 0).
- `voice/direct.rs` needed no change: it goes through `ChatClient`.

### WP2: record what the decision model says (done) `b48e973`

- `Answers::from_response` logs one `info` line per question: shape, decision (or the legacy `value`), confidence, probability and `p(picked)`; the one-time "shape seen" log is kept. No image data or task text. Example: `decision answer risk: shape=source decision="high" confidence=0.1374 probability=- p(picked)=0.4249`.
- New `Answers::picked_probability(name)`; used only for the log line. `confident_yes`, `choice` and all callers are unchanged. The shapes' doc comment now says the server returns the source shape.
- `agent/quick.rs` and all thresholds untouched.
- New test with the pasted answer: `choice("routing") == ("blue_green", 0.1374)`, picked probability 0.4249, `confident_yes("requires_approval", 0.68)` true and `0.69` false.

### WP3: warn when the model lists no Audio (done) `8f0aa04`

- `BackendStatus.model_capabilities` (camelCase `modelCapabilities`) from the configured model's `capabilities` (optional, default empty); `lacks_audio(&[String])` is false for an empty list and case-insensitive on `Audio`. TypeScript type updated.
- `toggle_listening` spawns the backend check in the background just before the microphone opens and logs a `warn` if the model was listed without `Audio`. **Deviation:** the handoff says "call the backend check", which I did, but in a spawned task so opening the microphone is not delayed by up to 8 s of probe timeouts. The warning can therefore appear slightly after the microphone opens. A failed check or empty list logs nothing.
- Outside the named files: `src/dev/mockTauri.ts` got `modelCapabilities: []` so the mock's `check_backend` object matches the type (the formatter wrapped that one line). `vue-tsc` could not be run here, so the type match is not machine-checked.
- Tests: capability parsing with and without the field, and `lacks_audio`.

## 4. NOT CERTAIN
