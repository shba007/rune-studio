# Working agreement

AI agents implement/test locally and leave changes unstaged and uncommitted.
Agents must not commit, push, merge, tag, publish or dispatch publishing workflows.
Preserve unrelated work; do not modify sibling repositories.

GitHub Actions IS authorized to calculate versions, update manifests/lockfiles/
changelogs, commit/push the dedicated release/update-version branch, open/update
the release PR and publish tags/releases/artifacts after owner promotion. The
human owner commits/pushes development work and reviews/merges release PRs.
Do not use AI services in release generation.

Use the small Rust utility under xtask (git-conventional, semver, toml_edit).
Commands from the repository root:

- cargo test --locked --manifest-path xtask/Cargo.toml
- cargo run --locked --manifest-path xtask/Cargo.toml -- prepare
- cargo run --locked --manifest-path xtask/Cargo.toml -- example
- cargo run --locked --manifest-path xtask/Cargo.toml -- notes

prepare defaults to a read-only dry run. Its --apply option writes release files
only and is for authorized CI preparation (or the owner); agents do not use it
on the working repository. It never stages/commits/pushes. Release versions and
substantive notes are normally generated by CI from reviewed conventional commits.
All semantic commit types trigger preparation, including docs, refactor, style,
test, build, ci, chore, revert and custom types. Only routine release automation,
autoformat bookkeeping, invalid commits and private/placeholder prose are excluded.
New public notes/suggested commit subjects must omit internal planning IDs.
Preserve historical sections, commits, tags and published releases. Publication
extracts the exact prepared CHANGELOG version section, never fresh history prose.

Vue CI triggers only on develop pushes, including merge/release commits.
Semantic commits prepare a PR after validation; generated release files are
checked in that same run. PR events and release-branch pushes do not start Vue CI.
Use GITHUB_TOKEN for release PR API operations and GH_TOKEN for branch pushes;
PR creation does not depend on the PAT having Pull requests write permission.
Only trusted develop pushes can prepare releases after all checks pass. One fixed
release branch/PR is reused. No releasable commits means no preparation PR.
.release/prepared.json records the consumed source head to stop preparation loops.
Merge the preparation PR into develop (merge or squash is supported). Then open
a develop → main promotion PR and use a MERGE COMMIT (not squash/rebase) to retain
reviewed history. Set its main merge commit title to ci(release): publish vX.Y.Z.
Merging into develop alone does not publish. See docs/RELEASING.md for tokens,
branch protection, local previews, artifact events and owner verification.

Prefer Rust for new repository-owned release utilities, protocol harnesses and
migration validation. Existing WinForms desktop fixtures and frontend/reporting
tooling are outside this focused release change; avoid broad rewrites.

Product contract: explicit Kit executable, then actual user home
rune/rune-kit[.exe], then PATH rune-kit[.exe]. No legacy rune fallback. Public
Studio → Kit MCP is 2026-07-28, Kit minimum 0.5.0. The private native/WASM plugin
ABI is unchanged. Studio remains an Infer HTTP client; Kit/Infer own installation
and storage migration. Never fall back to CWD on failed home resolution, overwrite
conflicting installation data or move unrelated project/model files.
